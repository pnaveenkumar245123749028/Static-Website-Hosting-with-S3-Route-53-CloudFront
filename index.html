Core AWS Services

How the architecture works

S3

Amazon S3

Stores the static website files such as HTML, CSS, JavaScript, and media assets in an organized bucket structure.

CDN

Amazon CloudFront

Delivers cached content from edge locations and routes requests over HTTPS while reducing latency for global visitors.

DNS

Amazon Route 53

Connects the custom domain name to the CloudFront distribution and resolves user requests to the right endpoint.

TLS

ACM

Issues and manages the SSL/TLS certificate required for secure HTTPS access on the custom domain.

Deployment Process

Step-by-step AWS hosting workflow

  1. Create a private Amazon S3 bucket and upload the static website files.
  2. Configure the bucket for website hosting with the correct index document, typically index.html.
  3. Prepare a CloudFront distribution and set the S3 bucket as the origin.
  4. Enable Origin Access Control (OAC) and attach the required bucket policy.
  5. Set the CloudFront default root object to index.html.
  6. Request and validate an ACM certificate in us-east-1 for your custom domain.
  7. Add the custom domain to the CloudFront distribution as an alternate domain name.
  8. Create Route 53 alias records that point the domain to the CloudFront distribution.
  9. Test the custom domain, verify HTTPS, and invalidate cache files after updates.

Security Considerations

Best practices for a secure setup

Recommended practices

  • Use a private S3 bucket instead of public access.
  • Use CloudFront OAC to allow controlled reads from the origin.
  • Enforce HTTPS with valid SSL certificates.
  • Grant least-privilege permissions only where needed.
  • Keep configuration details and AWS credentials out of frontend code.

Important reminders

Never place AWS access keys, secret access keys, account identifiers, private keys, passwords, or other secrets directly in frontend code or in the repository.

AWS services such as hosted zones, certificates, and distributions may incur charges, especially when using a custom domain and paid resources.

Testing and Validation

Checklist before presenting the project

Functional checklist

  • CloudFront URL loads successfully.
  • Custom domain resolves correctly.
  • HTTPS works without browser certificate issues.
  • CSS, JavaScript, and images load correctly.
  • Page links and navigation work on mobile and desktop.
  • Updated files appear after cache invalidation.

Architecture validation

  • The S3 origin is only reachable through CloudFront.
  • OAC is configured without exposing the bucket publicly.
  • Default root object points to index.html.
  • Route 53 alias records point to the CloudFront distribution.
  • The caching behavior matches the project requirement.

Conclusion

Why this hosting pattern is useful

Amazon S3, CloudFront, Route 53, and ACM together form a scalable and efficient way to host a static website with strong performance and a professional domain experience. This approach is especially useful for personal portfolios, academic projects, landing pages, and business websites that do not require a backend.

The important idea is that the content remains static while the architecture provides security, speed, and global delivery. The deployment and AWS configuration should be completed separately in the AWS Console or with infrastructure-as-code tools.
